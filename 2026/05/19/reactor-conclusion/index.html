what

什么是reactor？

Reactor 模式简介

Reactor 模式是一种 事件驱动架构模式，用于高并发 I/O 处理。
核心思想：事件检测与事件处理分离。

系统由两部分组成：
Reactor（事件分发器）：等待事件发生，分发给合适的处理器。
Handlers（事件处理器 / 回调）：实际处理事件逻辑（如 accept、recv、send）。

工作原理
注册事件：
将监听 socket 或客户端 socket 的可读/可写事件注册到 Reactor（你的代码用 epoll）。
等待事件：
Reactor 阻塞等待事件发生（epoll_wait）。
事件分发：
当事件发生时，Reactor 调用相应的回调函数：
处理事件：
回调函数完成实际 I/O 操作和状态管理。
根据需要修改事件类型（可读/可写），保持非阻塞连续处理。
特点
高并发：单线程也能处理大量连接。
非阻塞：只在事件发生时才处理，CPU 不会浪费在空等待上。
可扩展：每个连接维护独立状态和回调，便于管理。
核心：
事件循环 (epoll_wait)
事件注册/切换 (set_event)
回调函数 (accept_cb, recv_cb, send_cb)

在你的服务器中如何体现
epoll → Reactor（事件分发器）
conn_list 回调指针 → Handler（事件处理器）
event_register + set_event → 注册事件和切换事件类型

main() → 永久事件循环，检测事件并调用回调
状态机（status） → 控制响应流程，实现异步非阻塞

what

如何实现

1.struct conn保存每个连接的信息

int fd
write 和 read buffer
wlength和rlength
status（标记有没有io响应完成）
回调函数指针（accept和recv是或的关系所以使用union把这两个装在一起）

2.set_evnt(int fd, int event, int flag)

主要用于注册或修改epoll事件
检查非法的fd，错误返回-1
设置epoll_event结构体的fd和事件
根据flag判断fd是否存在，然后决定epoll_ctl是add还是modify
然后将事件加入或是修改事件

3.回调函数

accept_cb(int fd)

创建 clientaddr存储ip和端口
创建 len即clientaddr 的大小，accept要用到的参数
accept从监听socket接受一个新的客户端处理
错误处理，如果创建的fd小于0则返回-1
打印成功接受的信息
注册事件为epollin
返回0

recv_cb(int fd)

检查异常fd ，返回-1
recv接收到 fd对应的conn结构体的r buffer中
对recv返回值检查为0说明断开连接，关闭连接，通过epoll_ctl删除epoll中对应的fd
为-1说明出错，关闭连接，通过epoll_ctl删除epoll中对应的fd
调用http_request传入对应的数据
切换事件为epollout
返回接收到的数据长度

send_cb(int fd)

检查fd是否非法，非法返回-1
调用http_response()传入fd的struct conn
根据conn的status分别处理响应（为了处理buffer不够发的情况）
当然后根据status的值决定后续处理
status==1 发送储存在coon-》的wbuffer的http请求头
将事件注册为写，方便发送剩余的内容
status==2 将事件仍然设置为epollout让回调函数下一次被调用时才被改为epollin
status==0 将事件事件改为epollin

返回0

init_server()

用socket()建一个tcpsocket
初始化sock_addrin结构体设置协议，ip和端口
bind()绑定参数
检查绑定是否成功，错误则关闭fd，返回-1
listen()监听端口
返回监听的fd

event_register(int fd, int event)

初始化连接对应的conn结构体并且将事件注册到epoll当中
检测fd是否合法，不合法返回-1
初始化fd对应的conn
conn的fd=fd
buffer置0
status=0
调用set_event将event注册到epoll中
注意：listenfd的初始化和注册单独放在了main函数内容大致相同绑定的回调函数为accept_cb

main()

创建conn数组
创建epoll(1)创建epoll实例
for循环使用
init_server创建监听的fd
然后初始化对应的fd的conn
将accept_cb绑定到conn上
set_event将event设为为epollin并注册到epoll中

创建events数组
while(1)
用epoll_wait()函数接收对应的event并且保存到event数组
遍历event数组
如果状态是是epollin调用r_action的回调函数
如果是epoll_out调用sendcb

when

使用场景

why

为什么要使用reactor

  1. 高并发处理
    传统阻塞 I/O 每个连接需要一个线程，连接数量多时会消耗大量系统资源。
    Reactor 模式通过 单线程事件循环 + 回调，就能处理成千上万的客户端连接。
    你的服务器就是用 epoll + 回调实现了高并发客户端管理。
  2. 非阻塞异步
    Reactor 模式保证服务器不会在 recv() 或 send() 阻塞。
    事件发生时才处理对应回调，CPU 不会空转等待。
    提高系统吞吐量，降低延迟。
  3. 可维护性和解耦
    事件检测（Reactor）和事件处理（回调）分开。
    每种操作（accept/recv/send）都有独立回调。
    你的 conn_list + 回调机制就是典型的解耦设计，方便扩展功能（比如增加日志、认证、HTTPS）。
  4. 节约线程和资源
    不需要为每个客户端创建线程。
    减少线程上下文切换，节约内存和 CPU。
    Reactor + epoll 是 Linux 高并发网络编程的经典组合。

how

怎么使用

场景：异步文件/网络 I/O 服务

假设你要实现一个 服务器，既要处理客户端请求，也要读取磁盘文件（比如返回大文件或日志），希望 I/O 都非阻塞。

1️⃣ 初始化监听 socket
···c/c++
TCP 监听 socket，端口 3000：
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
bind(listen_fd, …);
listen(listen_fd, SOMAXCONN);
set_event(listen_fd, EPOLLIN, 1); // 注册可读事件
注册到 Reactor（epoll），等待客户端连接。
2️⃣ 回调函数设计
accept_cb
接收新客户端
初始化连接上下文
注册客户端 socket 可读事件，绑定 recv_cb
recv_cb
接收请求，例如客户端要求下载某个文件
不直接阻塞读取文件，而是：
打开文件描述符
将文件 fd 注册到 epoll 可读事件（或使用 O_NONBLOCK）
将文件内容读取逻辑交给 send_cb 处理
send_cb
发送缓冲区数据给客户端
如果文件还没读完：
异步读取下一块数据到缓冲区
继续注册 EPOLLOUT
文件读取完成 → 关闭文件 fd → 切回可读事件
3️⃣ 异步文件 I/O 技巧
Linux 提供 非阻塞文件 I/O：
int fd = open(“largefile.dat”, O_RDONLY | O_NONBLOCK);
使用 sendfile() 或 read() + send() 结合状态机发送数据
通过 Reactor 控制文件读取和网络发送：
status = 0 → 准备头部
status = 1 → 读取文件块
status = 2 → 发送完成
4️⃣ 事件循环
struct epoll_event events[1024];
while(1) {
int nready = epoll_wait(epfd, events, 1024, -1);
for(int i=0; i<nready; i++) {
int fd = events[i].data.fd;
if(events[i].events & EPOLLIN)
conn_list[fd].r_action.recv_callback(fd);
if(events[i].events & EPOLLOUT)
conn_list[fd].send_callback(fd);
}
}

场景：即时消息推送系统

假设你要实现一个 多人聊天室服务器，需要同时管理上千个长连接客户端，并实时转发消息。

1️⃣ 初始化服务器
创建监听 TCP socket，并绑定端口（如 5000）。
注册到 epoll 监听 可读事件（EPOLLIN）。
初次连接由 accept_cb 接受。
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
bind(listen_fd, …); // 绑定 IP/端口
listen(listen_fd, SOMAXCONN);
set_event(listen_fd, EPOLLIN, 1); // 监听可读事件
2️⃣ 客户端上下文
每个客户端连接维护独立上下文：
struct client_conn {
int fd;
char rbuffer[1024];
char wbuffer[1024];
int rlength, wlength;
int status;
RCALLBACK send_callback;
union { RCALLBACK recv_callback; RCALLBACK accept_callback; } r_action;
} client_list[MAX_CLIENTS];
status 用于区分：
0 → 等待消息
1 → 待发送消息
2 → 已发送完成
3️⃣ 回调函数设计
accept_cb
接收新客户端连接
初始化客户端上下文
注册客户端 socket 可读事件，绑定 recv_cb
recv_cb
接收客户端发送的消息
将消息广播到其他客户端
更新其他客户端的 wbuffer 和状态为可写（EPOLLOUT）
修改事件类型为可写
send_cb
发送缓冲区消息到客户端
发送完成后切换回可读事件（EPOLLIN）
4️⃣ 事件循环
Reactor 主循环：
struct epoll_event events[1024];
while(1) {
int nready = epoll_wait(epfd, events, 1024, -1);
for(int i=0; i 0 && i != sender_fd) {
memcpy(client_list[i].wbuffer, msg, len);
client_list[i].wlength = len;
client_list[i].status = 1; // 待发送
set_event(client_list[i].fd, EPOLLOUT, 0);
}
}
}
当某个客户端发送消息时，Reactor 模式保证 异步广播，不会阻塞其他客户端。

场景：多端口 TCP 服务

假设你要实现一个服务器，监听 多个端口，不同端口对应不同服务逻辑（例如 2000 端口处理 HTTP 请求，2001 端口处理 WebSocket，2002 端口处理自定义 TCP 协议）。

1️⃣ 初始化多个监听 socket
unsigned short ports[] = {2000, 2001, 2002};
int num_ports = sizeof(ports)/sizeof(ports[0]);

for(int i=0; i<num_ports; i++) {
int sockfd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_addr.s_addr = htonl(INADDR_ANY);
addr.sin_port = htons(ports[i]);

bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
listen(sockfd, SOMAXCONN);

conn_list[sockfd].fd = sockfd;
conn_list[sockfd].r_action.accept_callback = accept_cb;
set_event(sockfd, EPOLLIN, 1); // 注册可读事件

}

每个端口都会注册到 epoll，并且监听可读事件，由 accept_cb 处理新连接。

2️⃣ 回调函数设计
accept_cb
接受来自任意端口的新连接。
根据端口选择不同业务逻辑：
int accept_cb(int fd) {
int clientfd = accept(fd, …);

// 根据监听端口选择回调
if (fd == http_port_fd) {
    conn_list[clientfd].r_action.recv_callback = http_recv_cb;
} else if (fd == ws_port_fd) {
    conn_list[clientfd].r_action.recv_callback = ws_recv_cb;
} else {
    conn_list[clientfd].r_action.recv_callback = custom_recv_cb;
}

set_event(clientfd, EPOLLIN, 1);

}
recv_cb / send_cb
每个端口的客户端可以有独立处理逻辑。
发送和接收都通过状态机控制。
3️⃣ 事件循环
Reactor 主循环保持不变：
struct epoll_event events[1024];
while(1) {
int nready = epoll_wait(epfd, events, 1024, -1);
for(int i=0; i<nready; i++) {
int fd = events[i].data.fd;
if(events[i].events & EPOLLIN)
conn_list[fd].r_action.recv_callback(fd);
if(events[i].events & EPOLLOUT)
conn_list[fd].send_callback(fd);
}
}
事件循环统一管理所有端口和客户端。
不管端口多少，都由 epoll + 回调异步处理。
4️⃣ 优势
多端口统一管理 → 一个事件循环管理所有端口。
回调分发灵活 → 每个端口可绑定不同业务逻辑。
非阻塞高并发 → 支持同时处理大量客户端连接。
可扩展性 → 新增端口或协议只需增加初始化和回调，不改事件循环。

场景：物联网 / 传感器数据采集系统

假设你有 上百上千个传感器设备同时上报数据，服务器需要实时处理和存储。

1️⃣ 初始化监听端口
TCP 或 UDP 监听端口，例如 4000：
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
bind(listen_fd, …); // 绑定 IP/端口
listen(listen_fd, SOMAXCONN);
set_event(listen_fd, EPOLLIN, 1); // 注册可读事件
注册到 Reactor（epoll），等待传感器设备连接。
2️⃣ 客户端上下文设计
每个传感器连接维护独立上下文：
struct sensor_conn {
int fd;
char rbuffer[1024];
char wbuffer[1024];
int rlength, wlength;
int status; // 0:等待数据, 1:待发送回复, 2:发送完成
RCALLBACK send_callback;
union { RCALLBACK recv_callback; RCALLBACK accept_callback; } r_action;
} sensor_list[MAX_SENSORS];
3️⃣ 回调函数设计
accept_cb
接收新传感器设备连接
初始化上下文
注册客户端可读事件，绑定 recv_cb
recv_cb
从传感器读取数据到缓冲区
将数据写入数据库或消息队列（异步操作）
如果需要回复设备状态，将数据放入 wbuffer 并设置 status=1
注册可写事件（EPOLLOUT）
send_cb
发送缓冲区数据到传感器
发送完成后切换回可读事件（EPOLLIN）
4️⃣ Reactor 事件循环
struct epoll_event events[1024];
while(1) {
int nready = epoll_wait(epfd, events, 1024, -1);
for(int i=0; i<nready; i++) {
int fd = events[i].data.fd;
if(events[i].events & EPOLLIN)
sensor_list[fd].r_action.recv_callback(fd);
if(events[i].events & EPOLLOUT)
sensor_list[fd].send_callback(fd);
}
}
Reactor 统一处理所有设备事件
异步非阻塞保证高并发设备同时上传数据
5️⃣ 数据处理和状态机
status=0 → 等待数据
status=1 → 待发送回复
status=2 → 回复完成
回调和状态机结合，实现 异步接收和发送，不阻塞其他设备。
