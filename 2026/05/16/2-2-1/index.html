posix api 以及 epoll原理

posix api

服务器 客户端
socket() socket()
bind() bind()//optional
listen() connect()//udp可选
accept() recv()
send() send()
recv()

epoll_create()
epoll_wait()
epoll_ctl()

fcntl()

过程
1.建立连接
2.传输数据
3.断开连接

socket()

1.分配fd（由bitmap进行分配，及从前往后找到第一个没有使用的数字）
2.分配tcp控制块 alloc()

bind()

tcp控制块中会有个五元组 (源ip，源端口，目的ip，目的端口，协议)
bind就是将对应参数绑定
客户端没有绑定的话 connect()会随机分配一个端口

listen()

1.将tcp控制块的status设置为listen
2.为tcp控制块分配全连接队列（accept）和半连接队列（syn）

accept()

1.分配fd
2.fd到tcp的映射
3.epoll中管理accept应当使用水平触发（防止一次来多条连接）若使用边缘触发则应该如下所示

三次握手

seq表示此次发送的编号（实际上开始连接的编号是随机的，可以防止被攻击）
ack表示我期望再次接受到数据的编号（或者说在这个编号之前的数据我已经全部收到）
这些编号的作用：不丢失，不重复，不乱序

三次握手发生的函数
connect()对应第一次握手的客户端
listen()对应第二次握手的服务端（开启的是半连接syn）
accept()对应第三握手的服务端 （开启全连接accept）

tcp连接什么时候开始？
第一次握手时，listen()分配半连接队列时开始

第三次握手数据包，如何从半连接队列查找匹配节点
通过对应的五元组查找

syn泛洪怎么解决（就是客户端只做第一次握手创建半连接）
1.限制syn队列长度
2.限制syn+accept队列长度，即未分配fd的tcb数量
3.限制accept队列长度（更符合现代需求）

传输过程

send只是把数据拷贝到内核
怎么发送由内核的tcp协议栈控制

recv把内核数据拷贝到用户空间
怎么接收数据由内核的tcp协议栈控制

tcp协议

1.慢启动
2.拥塞控制
3.滑动窗口
4.延迟确认
5.超时重传

四次挥手

1.ack没有收到，先收到fin
2.双方都调用close
可以参考tcp状态转移图推导
